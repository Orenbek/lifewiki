# Topic synthesis

Synthesis organizes existing material into understanding that can be read continuously. It allows disagreement, mutual influence, and unfinished exploration. It does not require a contradiction-free theory of life.

## Establish scope and coverage

Align the topic scope with the request, read its entry page, and search for candidate pages. Read the main pages and necessary context. Check whether different terms actually address the same question. A retrieval agent's candidate list is not completed reading.

Work in batches when necessary. Report covered areas, unread candidates, and scope limits. Do not present partial reading as a complete map of the author's thought. Do not create empty domains or a fixed taxonomy of life to appear comprehensive.

## Find relationships with reasons

Identify adopted judgments, supporting experiences, sources, changes, and unresolved tensions. Relationships must be supported by page content. For example:

- One page explains a concept used by another.
- A judgment holds only under conditions explained elsewhere.
- Opposing experiences may arise from different circumstances whose differences remain to be understood.
- A later judgment revises an earlier understanding.

Organize these relationships directly. New claims about causes, motives, or values remain explicitly tentative interpretations. Keep material separate when no supported relationship is available; do not force a connection.

## Write a synthesis

The topic entry should explain its central concern, the understanding reached so far, how pages develop or challenge that understanding, and the main unresolved questions. These are content checks, not mandatory section headings. A small topic may need only a paragraph or two.

Put a brief synthesis in the topic README. Use a standalone introductory page for a substantial argument, with a summary and link in the README. Indexes should not duplicate articles. Explain why each step in a reading path follows, distinguishing recommended order from actual conceptual prerequisites. Each composed page should still be understandable when entered directly.

A recommended reading path does not by itself justify renaming pages. For a stable chapter series, use the `wiki-documentation` skill for numbered-series naming and maintenance; otherwise keep semantic filenames and express the order in the README.

For example, a link list covering choice, action, and feedback does not explain their relationship. A statement that feedback changes the basis of an earlier choice is a substantive judgment. Write it as adopted understanding only if the pages support it; otherwise pose it as a question for discussion.

## Coordinate edits and finish

After drafting the synthesis structure, use the main skill's alignment rules for new core interpretations. Change only pages, indexes, and links directly needed for this reading task. Preserve meaningful changes in understanding.

Verify that key synthesis judgments have support in material actually read, new explanations are clearly tentative, and the reading path exists with reasons for its order. Use the readability guide's independent reader check when substantially changing an article's main line.

Stop when the reader can explain the topic's concern, current understanding, reasons for page relationships, and remaining uncertainty. Report unread material and follow-up questions. Do not require eliminating every isolated item or disagreement.
