# Wiki Maintenance

## Audit

Start with the requested paths. Expand to directly affected indexes, links, claims, and overlapping pages. For a move, rename, merge, or deletion, search the repository for inbound links and plain-path references.

Check that:

- Substantive pages are discoverable from the nearest useful README, and index paths and descriptions match current content.
- README files remain concise navigation pages.
- Locations, names, and directory depth follow `directory-structure.md`.
- Relative link targets and fragments resolve.
- Substantive pages follow `frontmatter.md`.
- Knowledge, personal judgments, candidate interpretations, and meaningful historical changes remain distinguishable. Disagreements have context rather than being silently removed.
- Repeated knowledge has an authoritative source without collapsing distinct domain perspectives.
- `_meta` files other than the constitution have a current, documented purpose.
- Content still belongs in the Wiki under `governance.md`.

Follow the local constitution. Report apparent conflicts or obsolete constitutional rules instead of changing the constitution as routine maintenance.

## Repair

- Correct factual or navigational errors at their primary source, then update affected references. Return substantive changes of stance to the editor's alignment workflow.
- When merging pages, preserve unique personal material and meaningful differences in the destination, update references and indexes, then remove the source within the authorized scope.
- Before deleting a page, preserve any still-relevant unique knowledge and update its inbound references and indexes.
- After moving, renaming, merging, or deleting content, update Markdown links, plain-path references, README indexes, and affected Wiki configuration.
- Search for the exact old path and remove stale references while retaining accurate historical mentions.
- Preserve the authoritative destination's `created` value; update `updated` and optional tags according to `frontmatter.md`.

If a change revises constitutional domain boundaries or governance principles, treat the constitution update as a separate intentional governance change.

## Reorganize

Before a broad reorganization:

1. Map each source page to its destination.
2. State the navigation problem being solved.
3. Identify affected indexes, inbound references, and Wiki configuration.
4. Ask the user only when the mapping or scope is ambiguous or exceeds the request.

## Assess Freshness

Treat `updated` as the date of the latest meaningful edit, not a date when the author endorsed every statement. Assess views from their expressed context and report unresolved changes. Verify external facts with their sources when freshness is in scope.

## Finish

Confirm that:

- Affected files follow `frontmatter.md`.
- README indexes and descriptions reflect actual content.
- Relative links and fragments resolve.
- No stale reference to a moved, renamed, merged, or deleted page remains.
- Redundant explanations are reduced without erasing distinct perspectives. Unresolved tensions and meaningful changes remain visible.
- Constitutional issues are reported or handled as a separate intentional governance change.
